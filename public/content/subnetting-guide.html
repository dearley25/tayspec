Subnetting Without the Headache

Subnetting looks intimidating mostly because it's usually taught with the math first. Do it the other way: understand what you're trying to accomplish, then let the math follow.

What a subnet actually is

A network address splits into two parts: the network portion and the host portion. Subnetting just moves the line between them, borrowing bits from the host side to create smaller, separate networks out of one larger block.

Reading CIDR notation

An address like 192.168.1.0/24 means the first 24 bits are the network portion, leaving 8 bits for hosts. That gives you 256 addresses in the block — 254 usable, once you subtract the network and broadcast addresses.

A worked example

Say you're given 192.168.1.0/24 and asked to create 4 equal subnets. You need 2 extra bits to make 4 subnets (2² = 4), so you move the mask from /24 to /26. Each new subnet holds 64 addresses, 62 of them usable:

192.168.1.0/26   →  hosts .1  – .62
192.168.1.64/26  →  hosts .65 – .126
192.168.1.128/26 →  hosts .129 – .190
192.168.1.192/26 →  hosts .193 – .254

The shortcut worth memorizing

Once you know the block size (256 minus the last octet of the subnet mask), you can list every subnet boundary by just adding that block size repeatedly. For a /26, the block size is 64, so the boundaries are 0, 64, 128, 192 — exactly what's above.

Practice it before you need it

Pick a /24 block and try splitting it into 8 subnets, then 16. If you can do that on paper in under a minute, you're in good shape for both exams and real network design work.
