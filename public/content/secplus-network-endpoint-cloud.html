Network, Endpoint & Cloud Security

Part 4 of a Security+ (SY0-701) study series. This part moves from concepts into the actual tools that enforce them: firewalls, IDS/IPS, SIEM, VPNs, network segmentation, EDR/XDR, and virtualization — what each one is for, how it works, and where the real vendors sit in this space.

Firewalls

A firewall is a traffic control system. It sits between networks and decides what traffic is allowed and what's blocked, based on rules.

  • Packet-filtering (stateless) — the oldest, simplest type. Looks only at source IP, destination IP, port, and protocol, and doesn't track conversations. Fast but limited — e.g. "block all traffic from 203.0.113.10" or "allow TCP port 80."
  • Stateful — tracks connection state (NEW vs. ESTABLISHED) and automatically allows return traffic. The most common type in routers and business firewalls. More secure than stateless because it prevents spoofed response packets.
  • Next-generation firewall (NGFW) — combines the firewall with security inspection: it can see applications (not just ports), users, and content, and typically bundles IDS/IPS, application awareness, SSL inspection, and malware filtering. Example: allow YouTube but block YouTube uploads, or block BitTorrent even when it's tunneled over port 443.
  • Web application firewall (WAF) — protects web applications, not networks. Sits in front of websites and databases, defending against SQL injection, XSS, and CSRF, and operates at Layer 7 (HTTP/HTTPS).
Key point

A WAF protects the application. A network firewall protects the network. They are not interchangeable.

Firewall rules are processed top-down, first match wins, and rule sets almost always end with an implicit deny — for example: allow HTTPS from the internet to the web server, allow SSH from the admin network, deny everything else.

Real products worth knowing: Palo Alto Networks (NGFW leader), Fortinet FortiGate, pfSense (free, lab-friendly), and Cloudflare for WAF.

IDS vs. IPS

  • IDS (Intrusion Detection System) — monitors traffic for known attack signatures and anomalies, and alerts. It does not block traffic.
  • IPS (Intrusion Prevention System) — sits inline and can detect and block attacks in real time. More powerful, but carries a real risk of false positives blocking legitimate traffic.

Real tools: Snort and Suricata.

SIEM (Security Information & Event Management)

A SIEM centralizes logs from firewalls, servers, endpoints, and cloud services, then correlates events to detect attacks — providing alerts, dashboards, and reports. It matters because attacks are multi-step: a SIEM connects a login failure, a firewall alert, and a malware detection into one picture, turning noise into meaning.

Example detection chain: failed VPN logins → a login success from a new country → privilege escalation → data exfiltration. Individually these look unremarkable — together, the SIEM flags "this is not normal behavior."

Real platforms: Splunk, Microsoft Sentinel, and Elastic Security (ELK).

VPN (Virtual Private Network)

A VPN creates an encrypted tunnel that protects data in transit, used for remote access or site-to-site connections.

  • Remote access VPN — user to corporate network, used by remote workers, requires authentication.
  • Site-to-site VPN — network to network, connecting offices, data centers, or cloud VPCs.

The protocol is the rulebook for the tunnel: how it's created, how authentication happens, how encryption is applied, and how data is packaged and transported.

  • IPsec — a suite of protocols (not a single one), operating at the network layer (Layer 3), securing all IP traffic rather than just web traffic.
    • AH (Authentication Header) — integrity and authentication, no encryption, rarely used on its own.
    • ESP (Encapsulating Security Payload) — encryption, integrity, and authentication together; the most common choice.
    • Transport mode — encrypts the payload only; the original IP header stays visible. Used mostly host-to-host.
    • Tunnel mode — encrypts the entire original packet, including its IP header, and wraps it in a new IP header. Used for site-to-site VPNs.
  • SSL/TLS VPNs — use the same encryption as HTTPS, operate at Layer 7, and are often browser-based or use a lightweight client. The user authenticates through a browser or client, and the tunnel runs over TCP 443 — which makes it very firewall-friendly. Good fit for remote workers, BYOD, and contractors who need quick access without full network exposure.

Real tools: OpenVPN and WireGuard (modern, fast).

Network segmentation

Segmentation breaks a network into zones, limiting lateral movement (device to device to device) and blast radius (an IoT network's problems staying on the IoT network). If one system is compromised, an attacker can't automatically reach everything else — this is a critical defense against ransomware specifically. Real tools: VLANs (e.g. VLAN 10 for Sales, VLAN 20 for IT, VLAN 30 for Admins), firewalls placed between segments, and Zero Trust Network Access (ZTNA).

EDR vs. XDR

Traditional antivirus looks for known bad files and relies heavily on signatures. Modern attacks live off the land — abusing PowerShell, WMI, and macros — and leave behavioral traces rather than files. EDR and XDR exist to focus on behavior, context, and response instead.

EDR — Endpoint Detection & Response

Security technology that continuously monitors endpoint activity, records process behavior, detects suspicious actions, and enables investigation and response. Lives directly on workstations, servers, laptops, and phones — any device running an OS and executing processes.

EDR agents collect low-level telemetry: process creation, command-line arguments, file creation/modification, registry changes, DLL injection, network connections from a process, and privilege escalation attempts. It sees what happened, not just what file exists. Detection relies on machine learning, Indicators of Attack (IoA), and threat intelligence correlation — for example, flagging PowerShell launched by Word with an encoded command and an outbound connection to an unknown IP as malicious behavior.

When a threat is detected, EDR can kill a malicious process, quarantine files, isolate the endpoint from the network, roll back changes on some platforms, and alert the SOC. Its strength is excellent endpoint visibility, strong ransomware detection, and real-time response — its limitation is that it only sees the endpoint, and can miss attacks that start elsewhere.

Real platforms: CrowdStrike Falcon, SentinelOne, and Microsoft Defender for Endpoint.

XDR — Extended Detection & Response

XDR expands detection beyond the endpoint, correlating data from endpoints, network traffic, email, cloud workloads, and identity systems. It exists because attacks don't stay in one place — a modern kill chain might move through a phishing email, endpoint execution, credential abuse, and cloud access, and XDR connects those steps into one narrative.

XDR can respond across systems at once: isolate an endpoint, disable a user account, block an IP at the firewall, and revoke a token, all from correlated detections. It gives better attack context and fewer, faster alerts — at the cost of vendor lock-in risk and less customizability than a dedicated SIEM, with coverage that depends heavily on integrations.

Real platforms: Microsoft XDR, CrowdStrike Falcon XDR, and Palo Alto Cortex XDR.

How it fits together

  1. Phishing email delivered.
  2. User clicks the malicious link.
  3. Endpoint executes the payload.
  4. EDR detects the suspicious behavior.
  5. XDR correlates email events, endpoint behavior, and identity activity.
  6. Automated response triggers.
  7. Incident closes faster.

Virtualization

Virtualization runs multiple virtual computers (VMs) on one physical machine using software called a hypervisor — one physical server becomes many isolated virtual systems, each of which believes it's a real computer.

  • Type 1 (bare-metal) hypervisor — runs directly on hardware. More secure and efficient, used in enterprises. Examples: VMware ESXi, Hyper-V Server.
  • Type 2 (hosted) hypervisor — runs on top of an existing OS. Less secure, larger attack surface, typically used for labs and testing. Examples: VirtualBox, VMware Workstation.
Exam keyword

Isolation is the concept the exam is testing whenever VMs come up. If VM1 gets compromised, VM2 should stay safe — this limits the blast radius of an attack. But isolation does not mean invisible: a VM escape, where malware breaks out of one VM and compromises the hypervisor or other VMs, is the worst-case scenario for this model.

Snapshots are a point-in-time backup of a VM, letting you roll back quickly after a bad patch or a malware infection — take a snapshot, install updates, and if the update breaks something, roll back. Snapshots are fast rollback, not a substitute for real backups. VMs can also be cloned, migrated, and restored quickly — if the underlying hardware fails, a VM can be restored on another host within minutes.

Exam scenarios

  • Company wants strong isolation across multiple servers on one host → virtualization with a Type 1 hypervisor
  • Malware infects a VM and spreads to others → tests the concept of VM escape / hypervisor compromise
  • Security team wants fast rollback after ransomware testing → use VM snapshots

Quick reference

  • WAF protects the app; a network firewall protects the network
  • IDS alerts only; IPS can block inline
  • SIEM correlates logs across the whole environment into one signal
  • IPsec tunnel mode encrypts the whole packet; transport mode encrypts payload only
  • SSL VPNs ride over TCP 443, which makes them firewall-friendly
  • Segmentation limits lateral movement and blast radius
  • EDR watches the endpoint; XDR correlates across endpoints, network, email, cloud, identity
  • One box, many computers = virtualization; Type 1 = enterprise-grade isolation
