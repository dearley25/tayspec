Bash: Rotate Log Files Safely

A small script for compressing and rotating a log file, keeping a fixed number of old copies, without truncating a file an application still has open for writing.

The script

#!/usr/bin/env bash
set -euo pipefail

LOG_FILE="/var/log/myapp/app.log"
KEEP=5

if [[ ! -f "$LOG_FILE" ]]; then
  echo "No log file found at $LOG_FILE" >&2
  exit 1
fi

# shift existing rotated copies up by one, oldest first
for ((i = KEEP - 1; i >= 1; i--)); do
  if [[ -f "${LOG_FILE}.${i}.gz" ]]; then
    mv "${LOG_FILE}.${i}.gz" "${LOG_FILE}.$((i + 1)).gz"
  fi
done

# compress the current log into slot 1
gzip -c "$LOG_FILE" > "${LOG_FILE}.1.gz"

# truncate rather than delete, so the app's open file handle stays valid
: > "$LOG_FILE"

# drop anything past the retention window
find "$(dirname "$LOG_FILE")" -name "$(basename "$LOG_FILE").*.gz" \
  | sort -t. -k2 -n \
  | tail -n +"$((KEEP + 1))" \
  | xargs -r rm --

Why truncate instead of delete

If an application already has the log file open and you delete or rename it, the app keeps writing to the now-unlinked file — those log lines vanish once the process closes it. Truncating in place (: > "$LOG_FILE") keeps the same inode, so the app's file handle stays valid and new writes land in the fresh, empty file.

Wiring it up

Drop this in /usr/local/bin/rotate-app-log.sh, make it executable with chmod +x, and add a line to root's crontab to run it daily:

0 0 * * * /usr/local/bin/rotate-app-log.sh
